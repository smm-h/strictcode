## 0.2.0

The CLI moves onto go-strictcli v0.33.0: presence is declared at every flag and argument, a command that writes may no longer default a value, and `strictcode fix` takes its apply-or-preview decision as a required selector rather than a pair of booleans.

<details>
<summary>Context</summary>

Three v0.33.0 registration rules reach this CLI, and two of them needed a judgment the framework cannot make.

The mutating-default ban says absence must never resolve to a value the invocation did not state, because on a command that writes, a value the framework picked is a value the framework writes. Four declarations were refused. All four are paths -- a search root or a destination, never a value that lands inside an artifact -- so each moved its fallback into the handler and states it in `--help`, which is the remedy the rule names for exactly this case. `analyze` reads and never writes, so its declared defaults are untouched.

`MutexGroup` no longer exists; exactly-one selection is a choice flag. The `fix` command's apply-or-preview pair became a member-spelled selector rather than a token one, because the two options were already spelled as their own flags and a token selector would have rewritten the command line for no reason the rule asked for. It also closes a real hole: under the old boolean mutex `--no-apply` satisfied the group while electing nothing, so a negation could be read as a request for the other option. A member is elected by presence, so that input is now refused.

No command declares an update record. Each of the three would have had to invent a property flag that does not exist -- `fix`'s edits come from the graph, and the two generators rewrite a whole artifact -- and the reasoning is recorded at each registration site so a later reader does not re-open it as an oversight.

</details>

### Breaking

- **Breaking: `strictcode fix` takes its apply-or-preview decision as a required selector.** `--apply` and `--preview` are spelled exactly as before and exactly one is still mandatory, but they are now elected by presence: `--no-apply` and `--no-preview` are refused rather than quietly standing in for the other option. Absence no longer resolves to a tool-picked value on any command that writes — `fix`'s directory and `--config`, and `registry dump`/`matrix gen`'s `--out`, apply their fallbacks in the handler and state them in `--help`.
